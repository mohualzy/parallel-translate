# LaTeX 源码渲染设计

日期：2026-10-31

## 目标

网页、划词弹窗、侧栏里出现 `$\frac{a}{b}$` 这样的 LaTeX 源码时，译文里显示渲染好的公式，模型不改动公式。

不做：翻译整篇 `.tex` 文件；改动网页原文里的公式（硬性规则 2），双语模式下原文仍是源码；PDF 和视频字幕。已经渲染好的公式（KaTeX、MathJax、`<math>`）沿用现有的原样保留。

## 方案

### 识别

`src/lib/tex.ts` 的 `splitTex` 把文本切成普通文字和公式，支持 `$…$`、`$$…$$`、`\(…\)`、`\[…\]`。

`$` 的误判代价最高（`$5 and $10`、`$HOME/$USER`），所以：

- 开头的 `$` 后面、结尾的 `$` 前面不能是空白，结尾的 `$` 后面不能是字母、数字；
- 内容要像公式：有 `\命令` 或 `^ _ = + < >`，或者只是单个变量（`$x$`、`$x_1$` 这类）。

只看单个文本节点。公式被页面拆到多个元素里时不识别。

### 页面翻译

序列化时把公式换成 `<xN>` 占位，复用现有协议。占位引用的元素是扩展自己创建的 `<ptx-math>`，内容是源码，所以渲染失败时用户看到的是源码。

标签过多退回纯文本时没有占位，公式走普通文字。`deserialize` 对译文里的文字也跑一遍 `splitTex`，这条路径同样能渲染。

只有公式的段落：`plain` 退回用公式文本，走正常翻译流程，译文和原文相同时仍显示（否则这类段落永远没有渲染结果）。代价是这段多占一点 token，结果进缓存。

### 渲染

KaTeX 放在 background，输出 MathML 字符串，内容脚本解析后放进 `<ptx-math>`。

| 方案 | 取舍 |
|---|---|
| 内容脚本打包 KaTeX | 每个页面、每个 iframe 都要解析约 260KB 脚本 |
| 按需注入脚本 | 省掉上面的开销，但多一个注入入口和加载时序 |
| **background 渲染（采用）** | 翻译时后台本来就醒着；内容脚本不变大，也不用注入 |

输出 MathML 而不是 KaTeX 默认的 HTML：由浏览器排版，不用往网页注入字体和样式。

公式来自不可信的页面文本：KaTeX 用默认的 `trust: false`（`\href` 等不生效），`throwOnError: true`，解析失败时保留源码。

### 划词与侧栏

这两处没有占位协议，译文是纯文本。流式过程中显示文本，完成后切分并渲染。复制按钮复制译文原文，不读 DOM 文字（`textContent` 会混入 MathML 的内容）。

真实模型实测保留了公式（`just e2e-live`），prompt 不用改。

## 对用户的影响

- 只有页面上确实有公式时才多一次后台消息，普通页面没有开销。
- 扩展包增加 KaTeX 的体积，全部在后台脚本里。
- 公式显示依赖系统数学字体，字形和 KaTeX 默认的 HTML 输出不完全一样。
