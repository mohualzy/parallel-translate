# 长文术语一致性（AI 抽取文章术语）— 设计

## 问题

长文按「滚动到哪翻到哪」分成很多批请求，每批独立翻译，同一个术语前后可能译法不同。例如前面把 agent 译成「智能体」，后面译成「代理」；人名也会前后音译不一致，比如「马斯克 / 穆斯克」。用户术语表能解决固定的词，但每篇文章的关键术语不一样，不可能事先都写好。

## 方案

开启翻译后，如果页面是长文，就用一次请求让模型从正文里抽取最多 12 个「全文需要一致」的术语，并给出译法。之后每一批翻译都把这批文本里出现的术语注入 prompt，走和用户术语表完全相同的通道：只注入命中的条目，命中的条目计入缓存键。

### 抽取

- **什么算长文**：已识别段落的正文合计不少于 3000 字，适用于文章、文档、论文。社交媒体风格（时间线、评论流）、视频字幕不抽取：这些内容不是同一篇文章，术语没有「前后一致」的问题。
- **送什么给模型**：按文档顺序拼接段落纯文本，截取前 8000 字。术语大多在前文出现，限制长度能控制费用。
- **要什么**：最多 12 条，每行 `原文 = 译法`，直接复用术语表的解析器。要的是：反复出现的专业术语、概念名、需要翻译的产品 / 功能名、人名和机构名（固定译名）。排除：普通词、一次性的描述、整句。用户术语表里已有的词不重复抽取，冲突时以用户术语表为准。
- **防注入**：正文作为不可信数据放在 user 消息的标签里，system 里写明其中的指令不要执行（硬性规则 5）。
- **缓存**：按「模型 + 目标语言 + prompt 版本 + 正文」缓存抽取结果，再次打开同一篇文章不再请求。

### 不阻塞首屏，事后修正冲突

**取舍**：等抽取完成再翻首屏，前后最一致，但长文首屏会慢 2–4 秒，而首屏速度是这类工具最直观的体验。所以不等：首屏照常翻译，抽取并行进行。术语返回后，检查已经翻好的段落：原文命中了某个术语、译文里却没有采用该术语的译法，就带着术语重翻这一段。通常只涉及首屏的少数几段，代价是这几段的译文会在几秒后变一次。

抽取还没返回时就已发出、返回较晚的批次，用同样的规则检查：每段记下发送时的术语版本，返回后版本落后的，同样做冲突检查。

### 透明度

弹窗显示「本文术语 N 条」，可以展开查看抽取的术语和译法。觉得哪条不对，可以把正确译法写进术语表，术语表优先。

## 设置

设置项 `extractTerms`，默认开启，文案为「长文自动抽取术语，保证前后译法一致（每篇文章多一次请求）」。

## 不做

- **在译文上直接编辑术语**：先用术语表纠正，编辑译文属于 P3。
- **同时请求带术语和不带术语两版再合并**：费用翻倍，没有必要。
