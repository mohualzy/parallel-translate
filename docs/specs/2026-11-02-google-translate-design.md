# 内置 Google 翻译

## 目标

装好扩展不用配 API Key 就能翻译。配了自己的模型后，模型优先。

## 接口

用免 Key 的 `translate.googleapis.com/translate_a/t?client=gtx`。官方 Cloud Translation 需要 Key 和计费账号，做不到开箱即用。这个接口是非官方的，没有可用性保证。

实测（2026-11-02）：

| 请求 | 结果 |
|---|---|
| 同一请求带多个 `q` | 一次批量翻译，返回 `[[译文, 语言], …]`，12 段约 2400 字符正常 |
| `format=html` | `<g1>`、`<x1/>`、`<x1>…</x1>` 都保留，`&lt;` 保持转义；换行被压平，`'` 变成 `&#39;` |
| `format=text` | 保留换行，不转义 |
| 10 个并发 | 全部 200 |

## 方案

- **两种客户端**：`LLMClient` 收 prompt 返回文本，`MachineClient` 收原文返回译文。把上下文塞进 `complete()` 再让 Google 客户端反解 prompt 能少改调用方，但目标语言不在 messages 里，prompt 格式也会变成两边的隐式约定，所以分成两个接口。
- **分工**：网页、PDF、字幕的片段带占位标签，用 `format=html`；划词、输入框、侧栏是纯文本，可能多段，用 `format=text`。
- **内置服务不存储**：`getProviders` 总是把它排在最后，用户自己的模型优先成为当前服务；不能删除，设置页不显示模型相关字段。用户明确设为当前时才会优先用它。

## 依赖模型的功能

Google 不读 prompt，下面这些在它是当前服务时不生效：翻译风格、术语表、页面标题等上下文、长文术语抽取、视频预读、词典式释义。术语抽取和视频预读直接返回空结果，不发请求。

## 边界

- 国内网络直连不通，要走浏览器代理。连接超时时提示这一点，不提示调大超时。
- 接口失效时报错，用户改配自己的模型。不做备用接口。
