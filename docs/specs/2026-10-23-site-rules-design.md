# 常见网站适配规则 — 设计

## 原则

通用段落识别覆盖大多数网页，规则只修它在具体网站上确实出错的地方。每条规则都要先在真实页面上看到问题、再验证修好，不做大而全的规则表：依赖会随发版变化的类名的规则维护不起。

选择器只用稳定的属性：`data-testid`、`aria-*`、语义标签、长期不变的类名。不用 CSS Modules 带哈希的类名（如 `Box__0K17vj`），单元测试会检查这一点。

## 规则格式（`src/lib/site-rules.ts`）

| 字段 | 作用 | 什么时候用 |
|---|---|---|
| `hosts` | 主机名，含子域名 | — |
| `exclude` | 不翻译的元素，与用户的「不翻译的区域」合并 | 默认用它：选择器失效时退回通用识别，最坏是多翻几段 |
| `include` | 白名单：只翻译这些元素里的内容 | 只用于结构长期稳定、正文位置明确的网站：选择器失效时整页不翻 |

白名单内的内容不再经过「短界面文字」判断，因为短标题也是正文。判断看段落里的节点：HN 标题的段落容器是 `<td>`，白名单元素 `.titleline` 在它里面。手动的悬停翻译不受白名单限制。

设置项 `siteRules`（默认开）可以整体关闭内置规则。

## 实测发现（2026-10-23）

测法：Playwright 自带的 Chromium 加载 e2e 构建，配本地 mock 模型（每段加「【译】」前缀），访问真实页面后执行「立即翻译整页」，列出被选中翻译的段落。不花 API 费用，也不受后台标签页不渲染的限制。

| 页面 | 问题 | 规则前 → 后（段数） |
|---|---|---|
| HN 首页 | 每条标题下的「N points by X … \| hide \| N comments」、顶部导航、页脚都被翻译 | 66 → 30（只剩标题） |
| HN 评论页 | 评论头部「用户名 3 hours ago \| parent \| next」和每条「reply」占三分之二 | 只剩评论正文 |
| GitHub 文件查看页 | 代码不在 `<pre>`/`<code>` 里，每行一个 div，被逐行当成段落 | 2559 → 2 |
| GitHub PR diff | diff 表格的代码行、文件头、文件树 | 63 → 3 |
| GitHub 仓库首页 | 文件列表的文件名、每行提交信息（插入译文撑高表格） | 147 → 85（README 与侧栏） |

顺带修了两个通用问题，所有网站受益：
- **读屏专用标题**：带哈希类名的（`visuallyHidden__*`、`prc-src-InternalVisuallyHidden-*`）被当成正文翻译。
- **看不见的菜单**：`visibility:hidden` 的下拉菜单有盒子、也在视口里，懒翻译和「立即翻译整页」都会翻它。

## 没做的

- **X、Reddit**：当前网络下 Reddit 新旧版都被拦截（要求登录）；X 未登录时只显示登录墙，看不到推文；Playwright 的浏览器打开 X 直接被拒。没法看到真实问题，就不写规则。需要在已登录的浏览器里实测后再补。
- **注入 CSS 修排版**：这次实测的页面里没有需要它的地方，等遇到再加。
- **按路径区分规则**：现有规则按整个网站生效就够了。单页应用切换路由时还要重新匹配规则，等真有需要再做。
