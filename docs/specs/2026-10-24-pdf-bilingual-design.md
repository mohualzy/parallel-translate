# PDF 双语阅读器 — 设计

## 目标

在扩展里打开 PDF，左边原文页、右边译文页并排显示（也可只看译文）。译文页要像 PDF 自己排出来的，而不是在原文上贴一层带底色的文字框：原文字形去掉，背景、图片、线条保留，译文写在原段落的位置，用原文的颜色、字重和字体风格。翻译原则和网页翻译一致：代码、公式、专有名词不翻。

## 为什么自己做

用 pdf.js 在扩展页面里本地解析、渲染，发给模型的只有文字片段（AGENTS.md 硬性规则 7）。

## 原型结论（2026-10-24，arXiv 1706.03762 第 1、4 页，1810.04805 第 1 页，DeepSeek 实测）

1. **去字形**：渲染时把 canvas 上下文的 `fillText` / `strokeText` 换成记录函数，得到只有背景、图片、线条的「底图」，同时记下每个字形的文字、变换矩阵、颜色和字体。pdf.js 默认用 FontFace + `fillText` 画字，所以绝大多数 PDF 适用。Type3 字体是用路径画的，去不掉，见「边界」。
2. **真实字体名**：`getDocument({ fontExtraProperties: true })` 之后，`page.commonObjs.get(fontName).name` 能拿到原字体名，比如 `CMMI10`、`NimbusRomNo9L-Regu`。公式字体（CMMI / CMSY / CMEX …）和等宽字体据此识别。
3. **公式 / 代码作为原子**：段落里连续的公式字体、等宽字体片段（连同挂靠的上下标）作为一个原子。
   - 翻译时用 `<xN/>` 占位，DeepSeek 实测会原样保留并按中文语序放好。
   - 写回时，把原子的原始字形用原字体、按比例缩放后画到新位置，dₖ、d_model 这类上下标完整保留。
4. **译文里的英文用 PDF 自己的字体**：字体栈的第一位放 pdf.js 已注册的原文字体，中文回退到系统字体。所以译文里的 softmax、Transformer、引用年份和原文字形一致，比中文字体自带的拉丁字母自然得多。
5. **版面分析是关键**：原型里改过的问题都在这一层，要有单元测试兜住：
   - 宽下标把一行断成两截；
   - 根号等公式符号的基线不同，被当成独立的行；
   - 居中标题被首行缩进规则切开；
   - 行间公式被当成正文翻译。

## 流水线

```
pdf.js 文本项 ─▶ lib/pdf/layout：行（挂靠上下标、合并同基线片段）─▶ 段落块（同栏、字号相近、行距正常；
                首行缩进 / 短末行切段；居中对齐不切）─▶ 片段（原子换 <xN/>、断词连字符合并、转义）
                ─▶ 判定：翻译 / 保留（行间公式、纯代码、旋转文字、没有单词）
页面渲染 ───▶ 底图 + 字形记录 ─▶ 译文页 = 底图 + 保留块原字形 + 译文块排版绘制
```

**翻译**：复用网页翻译的批量请求（`translate` 消息），并附加 PDF 版面提示（不加括注、保持简洁，D50）。长文档先抽取文章术语再翻第一批（最多等 10 秒）。和网页不同，PDF 一页整体绘制，事后修正会让整页闪一次。
- **复用的能力**：缓存、术语表、文章术语抽取、风格档案、失败重试。
- **按页懒翻译**：页面接近视口时才翻译。
- **模型原样返回的块**（人名、机构名）保留原文字形，不重画。

**排版绘制**（`src/pdf/render.ts`）：
- **字体与颜色**：取块内正文字形的众数颜色和字重；衬线 / 无衬线跟随原字体名。
- **断行**：按原块宽度断行，中文逐字可断，英文单词和原子不可断，句读不放行首（避头尾）。
- **字号**：从原字号往下试，直到行数 × 行高装进原块高度，最小到原字号的 60%；仍装不下就按最小字号溢出。
- **对齐**：原块居中（各行中心对齐）时，译文各行也居中。
- **清底**：写之前，用块四周的背景色清空块区域，这样分数线、根号上横线这类跟着公式移走的矢量线不会残留。只在区域边缘颜色均匀时清，压在图片上的块不清。

## 界面（`src/entrypoints/pdf/`）

- 工具栏：文件名、显示方式（双语并排 / 仅译文）、风格（自动 / 各档案）、缩放（适合宽度 ± ）、翻译进度、打开本地文件。
- 页面：每页左右两个 canvas，接近视口才渲染和翻译，离开很远的页面释放 canvas，控制内存。
- 风格「自动」：首页文字含 Abstract 或有 arXiv 标记时用学术论文，否则用通用。

## 打开方式

| 入口 | 行为 |
|---|---|
| 弹窗：当前标签页是 PDF（地址以 `.pdf` 结尾，或 arxiv.org/pdf/…） | 「用双语阅读器打开」 |
| 右键 PDF 链接 | 「用双语阅读器打开 PDF」 |
| 阅读器内「打开本地文件」 / 拖放 | 用 File API 读取，不经过网络 |

**远程 PDF**：扩展页面凭主机权限直接 `fetch`，不受 CORS 限制。**`file://` 地址**：需要在扩展详情里开「允许访问文件网址」，否则提示用户改用「打开本地文件」。

**打包**：pdf.js 主模块和 worker 打进扩展；cMaps、标准字体用 WXT 的 `build:publicAssets` 从 `node_modules` 复制，约 2.3 MB。用 `isEvalSupported: false` 满足 MV3 的内容安全策略；扩展页面的 CSP 加 `'wasm-unsafe-eval'`，供 pdf.js 解码 JPEG 2000 图片。

## 边界（第一版不做）

- **Type3 字体**（一些老的 LaTeX 位图字体）：字形用路径画，去不掉，译文会叠在原文上。检测到时整页退回只显示原文并提示。
- **行内分数的分数线、根号上横线**：清底时一并清掉，分子分母仍在，但没有横线。行间公式整块保留，不受影响。
- **译文页不能选择复制文字**：后续可以加透明文字层。
- **扫描版 PDF（没有文字层）**：没有可翻译的文字，提示需要 OCR（P3）。
- **导出译文 PDF、点击 PDF 链接自动用阅读器打开**：后续再做。
