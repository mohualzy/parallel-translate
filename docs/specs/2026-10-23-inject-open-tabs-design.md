# 免刷新：给已打开的标签页注入内容脚本 — 设计

## 问题

Chrome 只在页面加载时注入 manifest 里的内容脚本，所以有两种情况页面里没有可用的脚本：

1. **安装前就打开的页面**：页面里没有脚本。弹窗显示「此页面无法翻译」，快捷键、右键菜单都没反应。
2. **扩展更新 / 重载后**：旧脚本还留在页面里，但它和扩展的连接已经断开，成了孤儿脚本。它留下的悬浮球、译文、划词按钮看得见，却用不了；点悬浮球没反应，弹窗也连不上。开发时每次 `just build` 后重载扩展都会遇到。

目前只能让用户手动刷新页面，而刷新会丢掉表单输入和滚动位置。

## 方案

### 两个注入时机

| 时机 | 做法 | 理由 |
|---|---|---|
| `runtime.onInstalled`（install / update） | 依次给所有已加载完的 http(s) / file 标签页注入 | 大多数情况下用户什么都不用做；这些页面如果正常加载，本来就会有脚本，不会多花资源 |
| 按需：弹窗、快捷键、右键菜单给页面发消息时报「Receiving end does not exist」 | 注入后重试发送 | 兜底：注入时还在加载的标签页、被丢弃（discarded）后恢复的标签页，或注入失败的标签页 |

跳过的标签页：
- 被丢弃的标签页：恢复时会重新加载，自带脚本。
- 还在加载的标签页：manifest 会注入，再注入一次就重复了。
- `chrome://`、扩展商店等：浏览器不允许注入，失败了也不处理。

注入什么：从 `runtime.getManifest().content_scripts` 里找匹配 `<all_urls>` 的那一条，取它的 `js` / `css`，不硬编码构建产物的文件名。用 `scripting.insertCSS` 和 `scripting.executeScript`，`allFrames: true`。需要新增 `scripting` 权限；`<all_urls>` 的主机权限已经有，所以安装时不会多出新的权限提示。

注入完成时，内容脚本还在异步初始化（要读设置），还没开始监听消息，所以重试发送要短暂轮询，最多约 3 秒。同一个标签页 10 秒内只注入一次：弹窗每秒都会查询一次状态，`chrome://` 之类的页面注入必然失败，不能每秒都去试。

### 新旧实例交接

新脚本启动时先在 `document` 上派发一个普通事件 `ptx-content-started`。WXT 自带的同类机制依赖 `CustomEvent.detail`，跨隔离世界读不到，孤儿脚本收不到，所以不用它。旧脚本收到事件后让自己的 `ctx` 失效，并做清理：
- 关闭翻译：移除译文，复原截断和标题，断开所有 Observer。
- 页面内 UI 由 WXT 跟随 `ctx` 自动移除。
- 页面事件监听统一挂 `ctx.signal`，失效时自动解绑。

**保留翻译状态**：翻译开启时，`<html>` 上带 `data-ptx-on` 标记。新实例在派发事件之前先读这个标记，如果开着，就在顶层页面上重新开启翻译。此时段落都在缓存里，很快恢复，也不产生费用。iframe 不单独恢复，跟随顶层页面的广播。

## 不做

- **YouTube 字幕**：页面世界的字幕钩子要在 `document_start` 包装 XHR，之后再注入已经错过播放器的字幕请求，所以仍需刷新页面。会在 README 里说明。
- **本次之前版本留下的孤儿脚本**：它们没有交接监听，第一次更新到含本功能的版本时，旧悬浮球可能和新的并存，刷新一次即可。以后的更新都能正常交接。
