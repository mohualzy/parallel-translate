# YouTube 双语字幕 — 设计

日期：2026-10-22 · 对应路线图 P2

## 要解决什么

在 YouTube 看外语视频时，画面下方同时显示原文和译文字幕。译文要准（整段上下文、术语表生效）、要跟得上播放进度，还不能多花钱（不看的部分不翻译）。

## 关键约束（为什么不能「直接去拉字幕」）

- 字幕的原始数据来自 `/api/timedtext`（`fmt=json3`）。2024 年起 YouTube 要求这个请求带上播放器内 BotGuard 生成的 `pot` 令牌，扩展自己拿 `captionTracks[].baseUrl` 去请求很可能拿到空结果。
- 播放器自己请求字幕时会带上令牌，所以**旁听播放器的请求**是唯一稳定的数据来源。

## 方案

```
页面世界（MAIN）                       隔离世界（内容脚本）                    后台
youtube-hook ──postMessage──▶ youtube-subtitles ──translate 消息──▶ translateSegments
 包装 XHR / fetch，只读取               解析 json3 → 字幕条目                     （复用批量协议、
 /api/timedtext 的响应                  按播放进度分批翻译                          缓存、术语表）
                                        在播放器内渲染双语字幕层
```

1. **旁听（MAIN world，`document_start`）**：包装 `XMLHttpRequest` 与 `fetch`，URL 含 `/api/timedtext` 时读取响应文本，用 `window.postMessage` 交给内容脚本。**不修改响应**，播放器行为完全不变；出错时静默跳过。内容脚本可能晚于播放器就绪，所以钩子缓存最近几次捕获的结果，内容脚本发「就绪」后再补发一次。
2. **解析（纯函数，`src/lib/subtitles.ts`）**：
   - 普通字幕：每个 event 就是一条字幕，取 `tStartMs`、`dDurationMs`、`segs[].utf8`。
   - 自动生成字幕（URL 含 `kind=asr`）：逐词滚动显示，直接翻译每一行会碎成半句。把所有词按时间拼起来，在句末标点、停顿超过 1.2 秒、或累计超过约 18 个词时断句，按句子显示和翻译。
   - 过滤 `[Music]`、`(laughs)` 这类环境音标注和 `>>` 换人标记。
   - URL 带 `tlang`（YouTube 已经机器翻译过）或字幕本身就是目标语言时，不处理，保留原生字幕。
3. **翻译（复用后台批量翻译）**：字幕条目就是「段落」，走现有的 `translate` 消息，因此缓存、术语表、漏段补翻都直接可用。上下文里注明「这是视频字幕」，并带上视频标题。**按进度翻译**：只翻译当前时间点之后约 2 分钟内的条目（每批最多 25 条），播放、拖动进度条时继续往后补；不看的部分不花钱。
4. **渲染**：字幕层挂在播放器元素（`#movie_player`）里，全屏时也能显示；用统一的 Shadow DOM 挂载（`mountPageUi` 增加锚点参数）。播放时逐帧读 `video.currentTime`，只在当前条目变化时更新 DOM。我们自己的字幕层显示期间，用 `html[data-ptx-subtitles]` 的 CSS 把原生字幕设为不可见（还在页面上，只是看不到），关掉后恢复。字号随播放器高度缩放；控制栏出现时上移，避免遮挡。
5. **开关**：设置项「YouTube 双语字幕」，默认开启。字幕的显示和隐藏跟随播放器自带的 CC 按钮（用户按 `c` 或点 CC 即可开关）；默认**不**自动打开字幕。自动打开会改变用户自己的播放器设置，我们先不这样做。「仅译文」显示方式沿用全局设置。
6. **优先人工字幕，标注自动字幕**（2026-10-22 实测后补充）：真实使用中发现，音乐视频的自动生成字幕会把伴奏和唱腔听成乱码，翻译只会如实转述乱码。所以当播放器加载的是自动字幕（`kind=asr`），而视频另有人工字幕时，切换到人工字幕：优先选与自动字幕同语言的，其次选英文，再次选任意一条；目标语言的人工字幕不选，因为那条原生字幕本身就能直接看，不需要双语。每个视频只切换一次，用户之后手动切回自动字幕不再干预。字幕轨列表和切换只能通过页面世界的播放器接口（`getOption / setOption('captions', …)`）操作，所以钩子在旁听到自动字幕时附带读取字幕轨列表，由内容脚本决定选哪一条，再发指令让钩子切换。钩子默认仍然只读。只有自动字幕可用时，字幕层显示「自动字幕」标记，提醒这一轨可能不可靠。
7. **切换视频**：YouTube 是单页应用，切换视频不刷新页面。字幕轨按 `v` 参数记录视频 ID，与当前 URL 的视频 ID 不一致时隐藏；新的 timedtext 到来后再切换。

## 不做 / 边界

- 不做画面 OCR，不支持烧录在画面里的字幕。
- 直播字幕（实时增量）、Shorts、嵌入式播放器（`/embed`）先不做，下一步再看。
- 广告期间不显示（广告不会请求同一视频的字幕）。
- 不在播放器控制栏加按钮：直接沿用 CC 按钮，避免改动 YouTube 的界面。

## 测试

- 单元：json3 解析、自动字幕合句、环境音过滤、按进度挑选待翻译条目。
- E2E：新增 `e2e` 构建模式，只在该模式下让 YouTube 脚本额外匹配 `127.0.0.1`（正式构建的 manifest 不变）。仿 YouTube 的测试页用 canvas 视频流当作时间源，点「CC」时由页面自己用 XHR 请求 mock 服务的 `/api/timedtext`，以此验证旁听、渲染、跟随进度、按进度翻译、CC 开关和隐藏原生字幕。
- 实测：用 deepseek-flash 在真实 YouTube 视频上手动验证一次（YouTube 对无头浏览器可能有限制，结果如实记录）。
