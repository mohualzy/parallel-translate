# 翻译风格档案（AI 助手）— 设计

## 目标

不同内容需要不同的译法：
- 技术文档要保留 API 名、术语用通行译法；
- 论文要严谨正式；
- 推特、Reddit 要口语、保留语气和梗；
- 小说要传神。

现在所有网页共用一段风格要求（默认值，或服务配置里的自定义要求）。把「风格」做成可切换的 prompt 档案，叠加在同一套翻译请求上，不为每个场景单独做一套翻译服务。

## 档案

| id | 名称 | 风格要点 |
|---|---|---|
| `general` | 通用 | 现有默认风格：忠实、通顺、像母语者写的 |
| `tech` | 技术文档 | 术语用业界通行译法；API、函数名、命令、参数、版本号、产品名保留原文；准确优先，不意译 |
| `paper` | 学术论文 | 严谨正式的学术语体；关键术语首次出现时括注原文；公式、变量、引用标记原样保留 |
| `news` | 新闻 | 客观简洁的新闻语体；人名、地名、机构名用通行译名；数字、日期、引语准确 |
| `social` | 社交媒体 | 口语化，保留语气、情绪和网络用语；梗和俚语用对应的地道表达；@用户名、#话题、链接保留 |
| `fiction` | 文学 | 传神优美，保留修辞、节奏与人物语气；对话符合人物身份 |

每个档案有中文、英文两版风格文本，跟随现有 prompt 的语言选择（目标语言是中文时用中文 prompt）。档案只替换「风格要求」这一段；分段协议、占位标签等格式约束不变，用户改不坏。

**服务配置里的自定义要求**：叠加在档案之后，作为「额外要求」。原来是自定义要求整个替换默认风格，现在改成叠加，这样设了自定义要求的用户也能用档案。这是行为变化，写进 DECISIONS。

## 选择规则（按优先级）

1. **用户为这个网站指定的档案**：在弹窗里选，存入 `siteProfiles`，按主机名保存。
2. **页面特征**：页面有 `citation_*` meta（arXiv、期刊、会议论文页的标准写法）时用 `paper`。
3. **内置主机名映射**：
   - `tech`：GitHub、Stack Overflow、MDN、`docs.*`、`developer.*` 等；
   - `paper`：arXiv、ACM、IEEE 等；
   - `news`：路透社、美联社、BBC、纽约时报等；
   - `social`：X、Reddit、Hacker News 评论区等。
4. 都不命中时用 `general`。

档案由内容脚本按当前页面解析好，随翻译请求发给后台（`PageContext.profile`）；后台据此取风格文本。缓存键里加入档案 id：换了风格，旧译文不会被误用。

字幕、划词、输入框不受档案影响：字幕已有专门的口语化提示，划词、输入框有各自独立的 prompt。

## 界面

- **弹窗**：新增一行「翻译风格」下拉框。选项是「自动（当前：技术文档）」加六个档案，选择后只对当前网站生效；选「自动」时清除该网站的指定。切换后当前页按新风格重翻，已翻过的内容按新的缓存键重新请求。
- **设置页**：说明各档案的含义，并列出已为哪些网站指定了档案（可删除）。

## 不做

- 用户自己新增、编辑档案：自定义要求已经能覆盖个性化需求，先不做档案编辑器。
- 用模型自动判断页面类型：要额外花一次请求，主机名加 meta 已经能覆盖常用网站。
