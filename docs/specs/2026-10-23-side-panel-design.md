# 原生侧栏：文本翻译 — 设计

## 目标

在不离开当前网页的情况下翻译任意一段文字。场景包括：
- 粘贴一段邮件、文档、聊天记录看译文；
- 把自己写的中文译成英文再复制出去；
- 网页上选中较长的一段，送到侧栏里慢慢看。

划词弹窗适合短句，读完就关；侧栏能长期停在浏览器右侧，适合长文本、反复修改和复制。

用原生 `chrome.sidePanel`；多服务 × 多语言并排对比属于路线图 P3「多模型对比」，这次只做单个结果。

## 界面（`src/entrypoints/sidepanel/`）

```
[翻译服务 ▾] [风格 ▾] [目标语言：自动（→ English）▾]
┌ 输入框（可粘贴、可编辑）──────────┐
└────────────────────────────────┘
[翻译]  Ctrl+Enter            [清空]
┌ 译文（流式显示）────────── [复制] ┐
└────────────────────────────────┘
```

- **目标语言「自动」**：输入不是目标语言（默认简体中文）时，译成目标语言；输入已经是目标语言时，改译成「输入框翻译」的目标语言（默认英文）。这样一个侧栏就覆盖了「看外文」和「写外文」两个方向，方向显示在下拉框里，也可以手动指定。
- **翻译服务、风格**：默认用当前服务和「通用」风格；可以临时切换，只影响侧栏，不改全局设置。
- **术语表**：同样生效，只注入命中的条目。
- **流式显示**：译文边收边显示。翻译过程中改了输入或再次点翻译，会中止上一个请求。
- **自动翻译**（用户反馈后补充）：
  - 粘贴即翻译。
  - 手动输入停顿 0.8 秒后自动翻译：连续打字不触发；输入法组字时不算，上屏后才计时；内容和设置都没变（如打了个字又删掉）时不重复请求；新请求会中止旧请求。
  - 清空输入即清空译文。
  - 已有译文时，切换服务、风格、目标语言自动重翻。
  - `Ctrl+Enter` / 按钮立即翻译。

## 请求

新的长连接 `ptx-text`，和划词共用同一套流式事件（`delta / done / error`）。断开即中止请求。后台 `translateText`：
- **prompt**：独立的文本翻译 prompt（`buildTextMessages`），要求保留段落、换行、列表和 Markdown，只输出译文。风格段复用档案文本，术语表照常注入。
- **防注入**：输入作为不可信数据放在 `<text>` 里（硬性规则 5）。
- **缓存**：按「服务 + 模型 + 目标语言 + 风格 + 命中术语 + 原文」缓存，和划词一样不排队、不重试。

## 打开方式

| 入口 | 行为 |
|---|---|
| 快捷键 `Alt+S`（可改） | 打开侧栏 |
| 弹窗底部「在侧栏翻译文本」 | 打开侧栏 |
| 右键菜单「在侧栏中翻译选中文字」（有选区时出现） | 打开侧栏，并把选中文字填进输入框、立即翻译 |

`chrome.sidePanel.open()` 只能在用户操作（点击、快捷键、右键菜单）的同一调用栈里调用，所以打开动作必须在这些事件的处理函数里直接调用，不能先 `await` 别的再打开。选中文字通过 `storage.session` 交给侧栏：侧栏打开时读取，已经打开时监听变化。不用消息传递，因为侧栏可能还没加载完。

Firefox 对应 `sidebar_action`，WXT 自动生成；打开用 `browser.sidebarAction.open()`。两者都没有时，在新标签页打开同一页面。

## 不做

- 多服务、多语言并排对比（P3）。
- 侧栏内的网页翻译控制：弹窗已经有了。
- 不支持原生侧栏时在页面里模拟侧栏：Chrome 114+ 都支持原生侧栏，退化为新标签页即可。
