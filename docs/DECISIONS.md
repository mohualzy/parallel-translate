# DECISIONS — 技术决策

格式：决策 → 为什么 → 对用户的影响。被推翻时不删除，标注「已废弃」并链接新决策。

## D1 WXT + TypeScript，而不是零构建的原生 JS

- **为什么**：MV3 内容脚本不能直接 `import` 其他文件，background / content / options 共享代码必须打包；WXT 负责生成 manifest、HMR、同时产出 Chrome 和 Firefox 版本。TS 让消息协议、设置结构在三个运行环境之间有类型约束。
- **影响**：需要 `pnpm install` 和一次构建才能加载扩展；换来的是改代码时类型错误在编译期暴露，而不是在某个网页上静默失败。

## D2 弹窗/设置页用原生 DOM，不用 React/Vue

- **为什么**：两个页面都是表单，状态简单；不引入框架可减少依赖和包体积，代码也更容易读懂。
- **影响**：扩展体积小、弹窗打开快。若设置页复杂到难以维护，再迁移到 Preact。

## D3 统一使用 OpenAI 兼容协议（Chat Completions）

- **为什么**：DeepSeek、通义、Kimi、智谱、硅基流动、OpenRouter、Gemini、Ollama 都提供该协议，一个适配器覆盖绝大多数模型。
- **影响**：用户填 Base URL + Key + 模型名即可接入；预设里提供常用 Base URL，模型名可从 `/models` 拉取，不写死可能过时的模型 ID。

## D4 模型请求只在 background 发出，且用流式

- **为什么**：内容脚本的跨域请求受网页 CORS 限制，且不应接触 Key。MV3 Service Worker 在「fetch 30 秒未收到响应」时会被终止，非流式请求在长批次上容易超时；流式响应几乎立即返回响应头。另外请求进行中定期调用扩展 API 保活。
- **影响**：慢模型（含推理模型）的长批次也不会因 Service Worker 被回收而失败。

## D5 多段合并成一次请求，用 `<s id="N">` 标记分段

- **为什么**：逐段请求延迟高、费用高（system prompt 重复计费），且单句缺少上下文。XML 风格标签比 JSON 更不容易被模型输出破坏（无需转义引号）。缺失段的补翻策略见 D14。
- **影响**：翻译更快、更省钱，上下文更连贯；个别模型偶尔漏段时会自动补翻。

## D6 富文本用编号占位标签保留

- **为什么**：链接、加粗、行内代码直接丢掉会让译文不可点击、代码被误译。把行内元素序列化为 `<gN>…</gN>`（需翻译）和 `<xN>…</xN>`（原样保留），译后按编号克隆原元素重建。标签不平衡或过多时降级为纯文本。
- **影响**：译文里的链接可点击、代码不被翻译；弱模型最多退化成纯文本译文，不会出错乱码。

## D7 对页面 DOM 非破坏性；仅译文模式用 CSS 实现

- **为什么**：移动或包裹 React/Vue 管理的节点会导致框架下一次更新时报错甚至白屏。我们只追加自有元素，隐藏原文用 `font-size:0` + 隐藏子元素，并给译文显式设回字号。
- **影响**：在 SPA 网站上更稳定；代价是少数「段落与块级元素混排」的片段在仅译文模式下仍显示原文。

## D8 缓存放 IndexedDB（background 内），不放 storage.local

- **为什么**：缓存条目多、需要按时间清理；storage.local 适合小配置，不适合大量键值。
- **影响**：重复浏览同一页面秒出译文、不重复计费；可在设置页一键清空。

## D9 API Key 存 storage.local，不存 storage.sync

- **为什么**：sync 会把 Key 同步到所有登录同一账号的浏览器；Key 属于设备级秘密。
- **影响**：换设备需重新填写 Key（或用导出功能并勾选包含 Key）。

## D11 默认不自动翻译短的界面文字

- **为什么**：在 GitHub、Wikipedia 上实测，按钮、标签页、导航链接、徽章的译文最容易撑乱布局，对阅读却几乎没有帮助。判定规则（`looksLikeUIChrome`）：不在 p/h*/td 等行文容器里，不超过 3 个词，并且处在链接/按钮里、整段只是一个链接，或者本身是行内块/flex 子项。
- **影响**：页面更整洁、请求更少（GitHub 首屏段落数 224 → 83）；需要时可以悬停按键单独翻译，或在设置里关闭这一行为。

## D12 悬停翻译在「松开按键」时触发

- **为什么**：按下 Ctrl 时还不知道用户是要按 Ctrl+C、Ctrl+点击，还是单按 Ctrl。等到松开时确认中间没有其他按键或鼠标点击，才算单按。
- **影响**：不会和复制、新标签打开链接等常用操作冲突。

## D10 E2E 用 Playwright 1.60.0 自带的 Chromium

- **为什么**：Chrome 137 起正式版禁止用 `--load-extension` 命令行加载扩展，自动化测试只能用 Chromium；1.60.0 对应本机已缓存的 chromium-1223，免去约 150MB 下载。
- **影响**：`just e2e` 开箱即跑；升级 Playwright 时需要 `pnpm exec playwright install chromium`。

## D13 内容被改写的段落等稳定 1 秒再翻译

- **为什么**：AI 对话、实时日志等页面会逐字改写同一段落，原实现每次变化都重新请求。解决办法是设一个段落稳定窗口。判定「被改写」有两条：原有节点的文本变了；或者动态扫描时，同一容器里的整段被换成了新内容（`textContent =` 这类写法会替换掉文本节点，只靠节点身份发现不了）。
- **影响**：E2E 中一段逐字输出的句子从 6 次请求降到最多 2 次；代价是被改写的段落要晚约 1 秒出译文，首次出现的新内容（如无限滚动）不受影响。

## D14 漏段补翻用二分 + 请求预算

- **为什么**：原实现对每个缺失段单独补发请求，模型输出整体乱掉时一批 12 段会变成 12 次额外请求。改为：缺失段对半拆成两组再请求，最多额外 2 次，剩下的标记失败让用户点重试。同一批内相同文本只发送一次。逻辑在 `src/lib/batch.ts`，可单测。
- **影响**：最坏情况的额外费用有上限；漏一两段时仍能自动补齐。

## D15 上下标、时间、图标字体原样保留

- **为什么**：`sup`/`sub` 多是引用角标、化学式、指数，交给模型反而可能被改写；`time` 是相对时间等元信息，翻译收益低；Material Icons 等图标字体靠文字连字显示图标，翻译后图标会变成文字。它们作为原子占位，译文中整体克隆；只有媒体和表单控件因为克隆有副作用而退化为纯文字。
- **影响**：引用角标仍可点击，图标正常显示，送给模型的标签更少。

## D16 目标语言为中文时用中文 prompt，并强调「每段都是完整翻译单元」

- **为什么**：网页里大量是短标题、标签，模型容易回复「请提供更多上下文」，所以为简体中文单独写了中文 prompt。格式约束不变，只调整措辞与语言。修改后 `PROMPT_VERSION` 升到 2，旧缓存不再复用。
- **影响**：短文本译文更稳定，中文输出更自然。

## D17 每个服务可配置额外请求参数（JSON）

- **为什么**：关闭推理模型思考、设置 Ollama `keep_alive` 等参数各家名字不同，无法统一成一个开关。直接让用户填 JSON 合并进请求体；`model`、`messages`、`stream` 不允许覆盖，保存时校验 JSON。
- **影响**：推理模型翻译可以显著提速、降低费用；填错时保存即报错，不会到翻译时才失败。

以下决策来自 2026-10-22 用真实 DeepSeek API 的实测。

## D18 连续两个 `<br>` 视为分段；纯文本片段用空的 `<ptx-t>` 锚点做懒翻译

- **为什么**：paulgraham.com 的文章整篇包在一个行内 `<font>` 里，段落用 `<br><br>` 分隔，结果整篇成了一段：一次请求 46 秒，译文是文末一大块。纯文本片段没有元素可观察，只能观察整个容器，懒翻译也随之失效。现在连续两个 `<br>` 视为分段（包含这种分隔的行内元素按块进入），单个 `<br>` 仍是段内换行；纯文本片段先在其后插入空的 `<ptx-t class="ptx-pending">` 作为观察锚点。
- **影响**：同一页面第一段译文 2.9 秒出现，只翻译滚动到的段落；代价是 `<br><br>` 分段的段落在仅译文模式下不隐藏原文（不是整段容器）。

## D19 `<article>` 内的短链接、短列表项算正文

- **为什么**：GitHub README 的目录列表（`<li><a>Quick Start</a></li>`）被「跳过界面文字」规则当成导航，只有超过 3 个词的一项被翻译，结果不一致。
- **影响**：文章里的目录、短列表都会翻译；`<article>` 之外的导航仍然跳过。

## D20 DeepSeek 预设默认关闭推理，提供可选的真实模型测试

- **为什么**：DeepSeek 当前模型（`deepseek-flash` / `deepseek-v4-pro`）默认开启推理。同一批两段文本实测：默认输出 175 token（其中推理 129），`{"thinking": {"type": "disabled"}}` 后 43 token，协议遵守情况相同。mock 测试证明不了模型是否遵守分段和占位标签协议，所以新增 `just e2e-live`，用真实 API 验证；它使用单独配置，不进 `just e2e`，未设置 `DEEPSEEK_API_KEY` 时跳过。
- **影响**：新建 DeepSeek 服务即为省钱配置；改 prompt 或协议后可以花几分钱跑一次真实验证。
